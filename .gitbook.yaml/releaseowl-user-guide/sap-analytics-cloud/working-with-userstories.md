# Working with UserStories

User Stories allow you to group and manage artifacts that are deployed together through a Release Pipeline.

#### Creating a User Story

* Navigate to **Change Management** and click on **User Stories**.
* Click **Create New User Story**.

<figure><img src="../../.gitbook/assets/image (2202).png" alt=""><figcaption></figcaption></figure>

* Fill in the required fields, such as:
  * **Summary**: A clear and concise name for the user story.
  * **Description**: Detailed explanation of the requirement or feature.
  * **Release Version**, **Sprint**, **Assigned To**, and any other custom fields as applicable.
* After entering the details, click the **Save** button to create the User Story.

<figure><img src="../../.gitbook/assets/image (2203).png" alt=""><figcaption></figcaption></figure>

* Once the User Story is created, it will appear in the list/grid view.
* Click on the **Edit** next to the User Story entry.

<figure><img src="../../.gitbook/assets/image (2204).png" alt=""><figcaption></figcaption></figure>

* Click on the **+Add** button to add **SAC Packages**.

<figure><img src="../../.gitbook/assets/image (2201).png" alt=""><figcaption></figcaption></figure>

* Click the **three-dot (More Actions)** menu.
* Select **Import Settings**.
* A pop-up message will appear, where you can enable the **Force Deploy** option. Click **Save** to apply the changes.

<figure><img src="../../.gitbook/assets/image (2200).png" alt=""><figcaption></figcaption></figure>

{% hint style="info" %}
**Note:  Force Deploy** — lets you redeploy the artifacts/agreements again even if it was already deployed.

* When _Force Deploy_ is enabled, version validation checks do not block the deployment.
* If the target environment version is higher than the source environment version, a warning message is displayed.
{% endhint %}

**Promote User Story:**

* Click on **Promote** to promote the user story.
